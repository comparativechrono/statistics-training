# Third-party software and data, and where they came from

These practicals are built on the [R workbench](https://github.com/comparativechrono/r-workbench), by way of the week 1 site, [r-training](https://github.com/comparativechrono/r-training), and like them they include programs and libraries that are licensed separately, and use others that the student's browser downloads while a page is running. Each of them keeps its own licence. In particular, the MIT licence of the Biowasm build framework does **not** change the licences of the programs that were compiled with it, and none of the licences below applies to the site's own text and code. (The data have sources and licences of their own: see [Data](#data).) If you copy or redistribute any of these files, please keep each component's notices and licence files with it.

The files in `assets/vendor/` are the same as those of the week 1 site, apart from pdf-lib and its fonts, which made that site's certificates and are not needed here.

## The terminal's command-line programs (WebAssembly, run in the browser)

These are the real programs, compiled to WebAssembly. They run on the student's own computer, inside the web page, in the Terminal tab of RStudio's Console pane. (The practicals don't use them, but they come with the RStudio tab.) Each folder `assets/vendor/biowasm/NAME/VERSION/` contains the program (a `.wasm` file and its JavaScript loader), its licence, a `NOTICE.txt` file (describing where the program came from, any local changes and where to find its source code) and a `SHA256SUMS` file of checksums. The folder of the base module only has a notice and checksums, because its licence is the Biowasm licence in `assets/vendor/biowasm/LICENSE.txt`. The four files at the top of `assets/vendor/biowasm/` (the runner, its licence and the two descriptions of the local changes) have their own `SHA256SUMS` file there.

Every `.wasm` file also contains parts of the Emscripten runtime and of its C library, musl (MIT licence), and, where a program needs them, LLVM's compiler support functions, compiler-rt (Apache 2.0 with LLVM exceptions). The JavaScript loaders were generated by Emscripten (MIT or University of Illinois/NCSA licence). The licence texts are in [assets/vendor/licenses/runtime-libraries/](assets/vendor/licenses/runtime-libraries/). All of these programs are written in C, and none of them contains a C++ library, zlib, bzip2 or liblzma.

**Where the builds came from.** GNU coreutils, gawk, grep 3.7 and sed, as well as the base module and the runner, come from the [Biowasm](https://biowasm.com) project. The programs and the base module were downloaded from `https://biowasm.com/cdn/v3/` between 30 September and 2 October 2026 (each `NOTICE.txt` gives the dates), and `aioli.js` is Aioli 3.2.3 as served by the same CDN. `diff` and `cmp` (GNU diffutils 3.10) and `grep-perl` (GNU grep 3.11 with PCRE2 10.42) were compiled for the workbench with Emscripten 6.0.10, so they are not Biowasm builds. `diff` was built from its release source without changes, and `cmp` with a one-line patch. grep and PCRE2 were also built from their release sources without changes, apart from one added function (`splice`) that Emscripten's C library lacks. The programs, the runner and their local changes are the same as in the Bioinformatics workbench, on which the R workbench (and so this site) is based. On 15 October 2026, `base.js`, `base.wasm`, `gawk.wasm` and `sed.wasm` were still identical to the files on the Biowasm CDN, and `aioli.js` only differed from the CDN's version by the local changes listed below. The way `diff`, `cmp` and `grep-perl` were built is described in [assets/vendor/licenses/diffutils-build/](assets/vendor/licenses/diffutils-build/) and [assets/vendor/licenses/grep-perl-build/](assets/vendor/licenses/grep-perl-build/).

**Local changes.** These are all listed in [assets/vendor/biowasm/RUNTIME-PATCHES.txt](assets/vendor/biowasm/RUNTIME-PATCHES.txt):

- The programs' JavaScript loaders record each program's exit status. The Aioli runner has two extra methods. `execIO` runs a program with real standard input, output and error, and starts every program afresh each time it is run, as happens with a process on Linux. `statTree` lists the shared file system in a single call. Their readable source code is in [execio-source.txt](assets/vendor/biowasm/execio-source.txt). The runner also keeps its worker where the page can stop it (when Ctrl+C is pressed twice).
- In each of the 17 **coreutils** programs and in **grep** 3.7, **one byte** of the `.wasm` file has been changed to make the C library's standard output unbuffered. Without this change, these builds lose any output that doesn't end with a newline (for example from `tr`, `head -c` and `fold`, or `grep -lZ` and `grep -z`). The changed byte, the reason for the change and the checksums of the files as they were downloaded are given in the [coreutils notice](assets/vendor/biowasm/coreutils/8.32/NOTICE.txt) and the [grep notice](assets/vendor/biowasm/grep/3.7/NOTICE.txt), and the script that makes the change is [unbuffer-stdout.py](assets/vendor/licenses/local-patches/unbuffer-stdout.py).
- In the loaders of **date** and **gawk**, the day of the year is counted in calendar days ([fix-day-of-year.py](assets/vendor/licenses/local-patches/fix-day-of-year.py)). As downloaded, `date -d 2024-07-15` printed “invalid date” in time zones that use summer time.
- `base.js`, `base.wasm`, `gawk.wasm` and `sed.wasm` have not been modified.

**Source code of the GPL programs.** The folder [assets/vendor/licenses/](assets/vendor/licenses/) (described in its [README.txt](assets/vendor/licenses/README.txt)) contains:

- the full text of version 3 of the GPL ([GPL-3.0.txt](assets/vendor/licenses/GPL-3.0.txt)) and of the Apache License 2.0 ([Apache-2.0.txt](assets/vendor/licenses/Apache-2.0.txt), which covers Comlink and wasm-feature-detect);

Their origins, sizes and SHA-256 values, and how each was checked against the upstream release (with its OpenPGP signature, and with the published checksum where the release announcement gives one), are recorded in [source-archives.json](assets/vendor/licenses/source-archives.json);

- for the Biowasm builds, the recipes (scripts and patches) for the four programs used here, taken from a single pinned commit of the Biowasm repository ([`97bb232`](https://github.com/biowasm/biowasm/tree/97bb23225892ba5cc59ba0deac8b212b957db66a)), in [biowasm-build/](assets/vendor/licenses/biowasm-build/). They are listed, with their checksums and their paths in that repository, in [biowasm-build-manifest.json](assets/vendor/licenses/biowasm-build-manifest.json). The commit and toolchain used for the original CDN builds are not known, so these recipes are provided so that the builds can be inspected and repeated; they are **not** a claim that rebuilding will produce identical binaries;

Section 6 of the GPL sets out the terms for distributing compiled programs together with their Corresponding Source. Anyone who hosts this site should keep `assets/vendor/licenses/`, the `NOTICE.txt` files and this file with it. The copyright statements of the programs, and of the code they include, are in their source releases; the licence given in the table above does not replace the notices in the individual source files.

## Downloaded while the page is running (not bundled)

- **webR 0.6.0**, which is R 4.6.0 compiled to WebAssembly, is downloaded by the student's browser from `https://webr.r-wasm.org/v0.6.0/` when the first R session starts (as soon as a practical's page opens, because the RStudio tab is shown first). After that, it is loaded from the browser's cache. Every R session in the page (RStudio's, `Rscript` and `R` in its terminal, and knitting) is a copy of webR. The site does not distribute it. As [webR's licence notes](https://github.com/r-wasm/webr/blob/v0.6.0/LICENSE.md) explain, R is licensed under versions 2 and 3 of the GNU GPL, the webR binaries (and the libraries compiled into them, which are listed there) are distributed under version 3 of the GNU GPL, and webR's other software (its setup and build scripts, the webR REPL and so on) is under the MIT licence unless its files say otherwise.
- **The R packages included in webR**: R's base packages (base, compiler, datasets, graphics, grDevices, grid, methods, parallel, splines, stats, stats4, tcltk, tools and utils, with the translations of R's messages, all part of R and licensed under the GNU GPL 2 or 3) and webR's support package, webr (MIT). R's recommended packages (MASS, Matrix, lattice and so on) are not included, because webR 0.6.0 builds R without them; like other packages, they are downloaded from the webR repository when they are installed.
- **The tidyverse**, which every practical asks students to install, is downloaded by the student's browser from the webR repository, `https://repo.r-wasm.org`, with the packages it depends on (about 100 in all). The site does not distribute them. On 19 October 2026, the core packages (tidyverse 2.0.0, dplyr 1.2.1, ggplot2 4.0.3, readr 2.2.0, tibble 3.3.1, tidyr 1.3.2, purrr 1.2.2, stringr 1.6.0, forcats 1.0.1 and lubridate 1.9.5) were all under the MIT licence. Most of the packages they depend on are too; the others are under the GNU GPL (for example knitr, digest and htmltools), the GNU LGPL (DBI), the Mozilla Public License (data.table), the Apache licence (RColorBrewer and utf8) or BSD-style licences (selectr, yaml and stringi). `packageDescription("NAME")$License` shows each package's licence in R.
- **Other R packages** are downloaded by the student's browser from the webR repository (CRAN packages built for webR) when the student installs them with `install.packages()`. They are also downloaded when a feature of the page needs them and the student agrees to install them: knitr and markdown for rendering a report (as every practical asks), shiny for running a Shiny app, and readxl and readr for Import Dataset, each with the packages it depends on. The site does not distribute them. Each package has its own licence, which `packageDescription("NAME")$License` shows in R. On 15 October 2026, the repository's builds for R 4.6 gave these licences (knitr's and markdown's were checked again on 19 October 2026, for knitr 1.52 and markdown 2.0): knitr GPL, markdown MIT, shiny MIT (version 1.13.0.8000), httpuv GPL (≥ 2), jsonlite MIT, readr MIT and readxl MIT.
- The **AI assistant** sends a student's messages (and, for the agent, its commands and their output) to the AI service the student has chosen (Google's Gemini API, Anthropic's API or an OpenAI-compatible service), using the student's own key. No AI model or service is part of the site.

## Data

The files in `data/` are copied into each student's `~/data` folder the first time they open a practical. They are made from public data, and [data/PROVENANCE.md](data/PROVENANCE.md) gives the source of each, the studies to cite and exactly what was done to it:

- `famuss.csv`, `hgdp_akt1.csv` and `virco.csv` come from the data page of Andrea Foulkes's book *Applied Statistical Genetics with R* (Springer, 2009). The page doesn't state a licence for them (see the note in PROVENANCE.md).
- `leukaemia.csv` and `all_expression.csv` are made from Bioconductor's data package ALL and annotation package hgu95av2.db, both under the Artistic License 2.0.
